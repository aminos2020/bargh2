# توان‌بان — سامانه‌ی مدیریت بهره‌برداری و پیمانکاری شبکه برق

وب‌اپلیکیشن سازمانی (Next.js 15 App Router + MongoDB + Iron Session) برای معاونت بهره‌برداری برق منطقه‌ای سیستان و بلوچستان، کارفرما و شرکت‌های پیمانکار — با ۷ نقش، گردش تایید سه‌مرحله‌ی گزارش کار، فهرست آحاد بها، صورت‌وضعیت، درخواست خرید، معادل‌سازی کارهای اضافی، امتیاز و رزومه، Audit Log، اعلان‌ها و PWA آفلاین.

---

## راه‌اندازی روی سرور خودتان

### ۱) نصب وابستگی‌ها
```bash
cd next-app        # محتویات این پوشه را می‌توانید مستقیم به ریشه‌ی ریپوی خود منتقل کنید
npm install
```

### ۲) MongoDB
```bash
# مثال با داکر:
docker run -d --name tavanban-mongo -p 27017:27017 -v tavanban-mongo:/data/db mongo:7
```

### ۳) تنظیم env
```bash
cp .env.example .env
```
- `MONGODB_URI` — آدرس دیتابیس خودتان
- `SESSION_PASSWORD` — حداقل ۳۲ کاراکتر تصادفی
- `MOBILE_ENC_KEY` — با دستور `openssl rand -hex 32` تولید کنید

### ۴) داده‌ی اولیه (فقط development)
```bash
npm run seed
```
کاربران seed (ورود با OTP — در حالت توسعه کد در **console سرور** چاپ می‌شود):

| نقش | شماره |
|---|---|
| معاونت (DEPUTY) | ۰۹۱۲۰۰۰۰۰۰۱ |
| رییس کارفرما | ۰۹۱۲۰۰۰۰۰۰۲ |
| کارشناس کارفرما | ۰۹۱۲۰۰۰۰۰۰۳ |
| رییس شرکت پیمانکار | ۰۹۱۲۰۰۰۰۰۰۴ |
| نماینده مقیم | ۰۹۱۲۰۰۰۰۰۰۵ |
| سرپرست گروه | ۰۹۱۲۰۰۰۰۰۰۶ |
| کارشناس شرکت (تکنسین) | ۰۹۱۲۰۰۰۰۰۰۷ |

### ۵) اجرا
```bash
npm run dev        # توسعه
npm run build && npm start   # عملیاتی
```

## تبدیل از حالت توسعه به عملیاتی (Production)

1. **کد OTP:** در حالت توسعه کد فقط در console سرور لاگ می‌شود. برای عملیات، بدنه‌ی `sendOtpByGateway()` در `lib/otp.ts` را به درگاه SMS خود (کاوه‌نگار، ملی‌پیامک و…) متصل کنید. در `NODE_ENV=production` نمایش کد به کلاینت **به‌صورت خودکار حذف می‌شود** و اگر درگاه تنظیم نشده باشد، ارسال خطا می‌دهد (امن).
2. **غیرفعال‌سازی seed:** `npm run seed` را در production اجرا نکنید؛ کاربران را از پنل معاونت/رییس شرکت بسازید (ثبت‌نام آزاد وجود ندارد).
3. **HTTPS الزامی است** — کوکی نشست `secure` و `httpOnly` است.
4. **PWA:** برای نصب روی موبایل، یک آیکون PNG در `public/icons/android-chrome-512x512.png` بگذارید و در `app/manifest.ts` به آرایه‌ی icons اضافه کنید (آیکون SVG فعلی برای نمایش کافی است).
5. **چندنودی:** rate limiter فعلی درون‌حافظه‌ای است؛ برای چند replica با Redis جایگزین کنید (`lib/rate-limit.ts`).

## نکات امنیتی پیاده‌شده

- OTP هش‌شده (SHA-256)، اعتبار ۲ دقیقه، محدودیت ۵ تلاش، rate limit روی check-phone/send-otp
- شماره موبایل: جستجو با هش، نمایش با AES-256-GCM (کلید از env)
- نشست Iron Session فقط شامل userId/role/organizationId/companyId
- همه‌ی APIها: role check + ownership/ایزولاسیون گروه‌ها سمت سرور
- Snapshot قیمت و عنوان آیتم بها در گزارش‌ها — تغییر قیمت، گزارش قبلی را تغییر نمی‌دهد
- حذف سخت ممنوع (isActive)، همه‌ی تغییرات مهم در Audit Log
- فایل‌ها: اعتبارسنجی نوع/حجم، نام تصادفی، سرو از route محدودشده
- خطاها فارسی و امن — هیچ جزئیات فنی به کاربر نمی‌رسد

## ساختار کلیدی

```
app/(auth)/login          ورود دو مرحله‌ای (شماره + OTP)
app/(panel)/<role>/...    ۷ پنل نقش‌محور (موبایل: BottomNav / دسکتاپ: Sidebar)
app/api/v1/*              همه‌ی endpointها — { ok, data | error }
lib/                      session, auth, permissions, encryption, otp, audit, ...
models/                   ۲۱ اسکیمای Mongoose (timestamps + softDelete)
services/                 منطق کسب‌وکاری: گردش تایید، گزارش، sync، تحلیل
components/               ui (۳۷) + layout + forms + domain + charts + pwa
scripts/seed.ts           داده‌ی توسعه
```

گردش گزارش: **تکنسین → سرپرست → کارشناس کارفرما → رییس کارفرما → معاونت + رییس شرکت** (تایید/رد/انجام مجدد/اختلاف — گزارش خودِ سرپرست مستقیم به کارشناس کارفرما می‌رود و خودتاییدی ممکن نیست).

مستندات بیشتر: `docs/api.md` و `docs/architecture.md`.
