# توان‌بان — سامانه‌ی مدیریت نیروی انسانی و گزارش کار بهره‌برداری برق

وب‌اپ سازمانی فارسی/RTL برای معاونت بهره‌برداری برق منطقه‌ای سیستان و بلوچستان، کارفرما و شرکت‌های پیمانکار.
هفت نقش: معاونت، رییس کارفرما، کارشناس کارفرما، رییس شرکت پیمانکار، نماینده مقیم، سرپرست گروه، کارشناس شرکت (تکنسین).

## اجرا

```bash
npm install
npm run dev        # توسعه روی http://localhost:5173
npm run build      # خروجی production در پوشه‌ی dist
npm run typecheck  # بررسی TypeScript
```

خروجی `dist` استاتیک است و روی هر وب‌سرور (Nginx، Caddy، هاست اشتراکی) سرو می‌شود.

## تبدیل از حالت آزمایشی به عملیاتی

1. **حذف خودکار ورود آزمایشی:** دکمه‌های «ورود آزمایشی» و نمایش کد OTP فقط در حالت توسعه (`import.meta.env.DEV`) رندر می‌شوند. دستور `npm run build` به‌طور خودکار همه‌ی این‌ها را از خروجی حذف می‌کند؛ نیاز به تغییر کد نیست.
2. **سرو dist روی سرور خودتان:** فایل‌های `dist` را پشت Nginx/Caddy با هدرهای امنیتی و HTTPS سرو کنید.
3. **داده‌ها در حالت فعلی local-first هستند** (localStorage/IndexedDB هر مرورگر + صف sync با idempotencyKey). این برای پایلوت و دمو کامل است؛ برای محیط عملیاتی چندکاربره به بک‌اند نیاز دارید (بند بعد).

## معماری و مسیر مهاجرت به Next.js + MongoDB

این workspace فقط build استاتیک Vite تولید می‌کند؛ لایه‌ی سرور واقعی (Next.js App Router + Mongoose + Iron Session طبق مشخصات) باید روی ماشین خودتان اجرا شود. نکته‌ی مهم این است که کل اپ طوری طراحی شده که این مهاجرت مکانیکی باشد:

| لایه‌ی فعلی (کلاینت) | معادل سرور |
| --- | --- |
| `src/types.ts` (همه‌ی entityها و وضعیت‌ها) | Mongoose Schemaها — فیلدها ۱به۱ منطبق‌اند |
| `src/store.tsx` (توابع mutate: ارسال گزارش، گردش تایید، آudit، اعلان) | API Routeهای `/api/v1/*` — منطق عیناً منتقل می‌شود |
| نشست در localStorage | Iron Session با کوکی httpOnly/secure (فقط userId/role/orgId/companyId) |
| نمایش OTP روی صفحه | ارسال SMS با کاوه‌نگار/ایپنل؛ hash کد با SHA-256 + salt |
| صف Sync در localStorage | همان SyncQueue با idempotencyKey — endpoint سمت سرور اضافه می‌شود |
| seed در `src/data/seed.ts` | اسکریپت seed روی MongoDB |

مرحله‌ی عملیاتی: کلاینت همین می‌ماند؛ فقط `store.tsx` پشت fetch به API واقعی قرار می‌گیرد و بقیه‌ی UI دست نمی‌خورد.

## نکات امنیتی (پیاده‌شده در سطح کلاینت)

- ورود فقط برای شماره‌های ازپیش‌ثبت‌شده؛ کاربران غیرفعال بلاک می‌شوند.
- OTP: ۵ رقم، انقضای ۲ دقیقه، محدودیت ۵ تلاش ناموفق.
- normalize موبایل (ارقام فارسی، +98، 0098 → 09xxxxxxxxx).
- گزارش‌ها ایزوله بر اساس عضویت گروه؛ هر نقش فقط داده‌ی مجاز را می‌بیند.
- Snapshot قیمت و عنوان آیتم هنگام ثبت گزارش (تغییر بها روی گزارش قبلی اثر ندارد).
- idempotencyKey برای جلوگیری از ثبت تکراری هنگام sync.
- حذف سخت وجود ندارد؛ فقط غیرفعال‌سازی (isActive).
